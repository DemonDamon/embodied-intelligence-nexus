# 8.4 DriveVLA-M0：故障记忆增强与测试时适配的自动驾驶 VLA

> 作者：Damon Li | 更新日期：2026年8月25日
> 证据状态：预印本 + 官方代码；26.44 ms 是 NAVSIM 中 TTT 反向传播的额外开销，**不等于**完整车端感知—规划—执行链路时延。

## 1. 结论与证据等级

DriveVLA-M0 是面向自动驾驶的 retrieval-augmented VLA。其离线阶段构建保存历史失败案例、结构化场景表征和专家轨迹标签的 latent memory pool；在线阶段以静态道路结构与动态交通参与者解耦的 Retrieve Model 检索相似场景，并通过 decoupled LoRA-based test-time training（TTT）做场景化修正。[1] [2]

论文摘要报告 NAVSIMv1 Navtest 上的 94.1 PDMS、NAVSIMv2 Navhard 上的 47.0 EPDMS，以及 26.44 ms 的 TTT backward latency overhead。[1] 这些是特定仿真基准和论文协议下的结果，不能表述为真实道路安全性，也不能直接和机械臂 VLA 或人形机器人控制时延比较。

## 2. 问题设定、符号与假设

令当前驾驶场景为 $o_t$，失败案例记忆池为 $\mathcal M=\{(k_i,e_i,\tau_i^*)\}$，其中 $k_i$ 是检索键，$e_i$ 是场景表征，$\tau_i^*$ 是专家轨迹标签。系统目标是避免模型在已出现过的相似失败模式中持续失效：

$$
z_t=R_\psi(o_t,\mathcal M),\qquad
\theta'_t=\operatorname{TTA}(\theta,z_t),\qquad
\hat\tau_t=\pi_{\theta'_t}(o_t,z_t).
$$

该结构依赖三个强假设：记忆中的失败标签具有足够质量；当前场景与历史失败场景可被结构化检索正确匹配；局部 LoRA 适配不会引入新的安全退化。[1] [2]

## 3. 方法与完整推导

离线记忆生成把由 oracle 仿真指标识别的 failure-prone scene 写入潜空间记忆池；在线 Retrieve Model 分别编码地图和智能体线索，再将相似案例用于轻量 TTT 修正。[1] [2] 如果以检索到的专家轨迹为适配监督，常见的局部目标可写为

$$
\mathcal L_{\mathrm{TTT}}(\theta;z_t)=
\|\pi_\theta(o_t,z_t)-\tau^*_{\mathrm{retrieved}}\|_2^2.
$$

此式仅是论文“检索 + LoRA 测试时适配”机制的抽象重建。公开摘要未逐项给出触发阈值、损失权重、更新步数、是否使用额外正则或线上回滚策略；这些必须以代码与论文全文为准。

## 4. 训练和推理算法

离线流程依次为：识别失败场景、写入场景/轨迹簇/专家信号、训练或配置检索模型。在线流程依次为：抽取 map 与 agent 键、检索结构相似案例、注入相应记忆并仅对局部 LoRA 进行 TTT，最终输出规划轨迹。[1] [2]

官方仓库提供 NAVSIM 1.1 的 Base Model 和 Retrieve Model 部署路径、Hydra 配置、检索可视化工具及 PDMS 评测脚本。[2] README 也说明该 release 面向部署与 checkpoint 验证，故应逐条核查是否覆盖论文的全部记忆构建与 TTT 训练管线。

## 5. 实验设计、基线与结果

| 维度 | 论文报告 | 正确解读 |
|---|---|---|
| 基准 | NAVSIMv1 Navtest、NAVSIMv2 Navhard [1] | 仿真/评测协议，不是公开道路安全认证 |
| 指标 | 94.1 PDMS、47.0 EPDMS [1] | 仅在对应版本、数据与评分条件下可比较 |
| 时延 | 26.44 ms TTT 反向传播额外开销 [1] | 不包含完整感知、检索、骨干推理、车辆执行闭环 |
| 扩展性 | 论文报告记忆增加可带来免重训性能增益 [1] | 仍需检查检索存储、延迟和错误记忆累积 |

## 6. 失败模式、局限性与复现条件

该方法把“失败”识别依赖于 oracle 模拟评分；现实道路不一定拥有同样及时、可信的真值。检索阈值过低会引入无关记忆，过高则错过修正机会；局部在线更新也可能使模型在短时适配后损害常规场景性能。评估还应覆盖长尾交通参与者、地图变化、传感器退化、记忆污染、版本回滚和安全兜底。

复现依赖 NAVSIM、nuPlan/OpenScene 工具链、显存资源及官方 checkpoint。对任何真实车辆部署，应把仿真分数、TTT 计算开销、端到端实时性和安全验证分开报告。
