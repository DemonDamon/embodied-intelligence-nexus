# 7.22 XCoT-VLA：面向自动驾驶的可执行思维链与轨迹生成

> 作者：Damon Li | 更新日期：2026年8月25日
> 证据状态：预印本论文 + 公司官方世界模型披露；XCoT-VLA 的代码、权重与完整数据**未在本轮核验到**。

## 1. 结论与证据等级

XCoT-VLA 是小鹏 Foundation Model Team 的自动驾驶 VLA 预印本。其核心不是把自然语言思维链直接用于控制，而是从自动构建的 Reason–Action 监督中学习 **2–6 个可执行 token**，再以确定性 token-function routing 将推理 token 与轨迹查询分配给不同 FFN 流，最终以 flow matching 生成连续驾驶轨迹。[1] 论文摘要报告通用分布集的 longitudinal ADE 由 1.645 降至 1.323、变道场景 lateral FDE 由 1.616 降至 0.648。[1]

小鹏官方披露的 X-World 是另一个相邻对象：它是用于多视角可控视频生成、闭环仿真、在线强化学习和数据生成的驾驶世界模型，支撑第二代 VLA 的研发与验证。[2] 因此，**不能把 X-World 的公司生产应用披露直接视作 XCoT-VLA 已量产或已独立复现的证据**。

## 2. 问题设定、符号与假设

令 $o_{\le t}$ 表示多摄像头历史观测与场景上下文，$r_{t:t+K}$ 表示紧凑可执行推理 token，$q$ 表示固定轨迹查询，$\tau_{t:t+H}$ 表示未来连续轨迹。目标是避免开放式自然语言 CoT 的长 token 解码延迟，同时保留语义推理对轨迹规划的条件作用：

$$
\hat r=\pi_{\theta}^{\mathrm{reason}}(o_{\le t}),\qquad
\hat\tau=\pi_{\theta}^{\mathrm{control}}(o_{\le t},\hat r,q).
$$

该设定隐含三个关键假设：第一，离线轨迹与场景可构成可靠的 Reason–Action 监督；第二，紧凑 token 空间足以表达驾驶决策中的关键因果语义；第三，轨迹生成器在 token 压缩后不会丢失对长尾交互的必要信息。[1]

## 3. 方法与完整推导

论文公开摘要确认 Reason FFN 预测 XCoT token、Control FFN 对轨迹查询进行 flow-matching 轨迹生成。[1] 可据此重建联合训练骨架：

$$
\mathcal L(\theta)=\lambda_r\mathcal L_{\mathrm{token}}(\hat r,r)+
\lambda_\tau\mathcal L_{\mathrm{FM}}\big(v_\theta(x_s,s\mid o,r),v^*(x_s,s)\big).
$$

其中 $\mathcal L_{\mathrm{token}}$ 可理解为离散 token 的监督损失，$\mathcal L_{\mathrm{FM}}$ 让网络拟合从噪声轨迹 $x_s$ 到目标轨迹的条件速度场。上式是基于公开模块说明的**补充重建**，不是论文摘要披露的完整损失、权重、采样日程或 XCPO 奖励函数。论文仅将 XCPO 描述为同一 token 空间中的可选 refinement extension，因而不能推断其对安全性、合规性或长尾风险已具备何种保证。[1]

## 4. 训练和推理算法

训练阶段，系统从 logged trajectory 与场景上下文构建 Reason–Action 监督；Reason 流预测紧凑 XCoT 序列，Control 流在该序列条件下生成轨迹。[1] 推理阶段先输出 2–6 个 token，再通过共享多模态上下文和固定轨迹查询生成连续轨迹。确定性路由的目的在于减少不同 token 类型共享 FFN 时的计算与功能冲突。

公开摘要没有披露动作块长度、噪声/采样步数、控制频率、缓存刷新策略、端到端硬件时延或安全后处理；这些必须在代码、技术报告或实验附录公开后才可复核。

“推理延迟问题被解决”应被严格改写为：论文声称紧凑 token 减少自回归开销并处于实时规划预算内；**摘要不提供可独立复核的端到端毫秒延迟与硬件配置**。[1]

## 6. 失败模式、局限性与复现条件

可执行 token 词典可能对驾驶领域强耦合，向通用机器人操作迁移时需要重新定义 token、监督管线和动作接口。更重要的是，离线数据覆盖、动作标签质量、罕见交互和从感知错误到轨迹风险的传播，都可能破坏紧凑表示的充分性。公司页面披露的 X-World 可用于闭环仿真，但生成视频质量与规划安全性仍需通过独立协议验证。[2]
